# What's new

**What's new in 0.7.6** (2026-10-19; [CHANGELOG](../CHANGELOG.md#076---2026-10-19)): a jevmem plugin for Cursor.

- **Install jevmem as a Cursor plugin.** `cursor-plugin/` in the repository, listed in the new `.cursor-plugin/marketplace.json`, carries the five hooks that save each finished agent turn, the MCP server the agent reads memory over, and the rule that tells it to, in every Cursor window at once, so a project needs no `.cursor/` files from jevmem: `jevmem setup` turns it on, and elsewhere the plugin stays silent (its hooks exit at once, its server answers that jevmem is off there, its rule tells the agent to leave jevmem alone). Like the Claude Code plugin it ships no code and runs the `jevmem` CLI from npm through one shell launcher, with the key from `jevmem key`. From the Cursor Marketplace once it is listed there; now by copying the folder to `~/.cursor/plugins/local/jevmem` ([the steps](install.md#the-cursor-plugin-076)). *What Cursor does with a plugin was measured before the design, on Cursor 3.25.9 and the `agent` CLI 2026.10.16: a plugin's MCP server starts in every window on load with no toggle, from the home folder with `${workspaceFolder}` expanded per window (the CLI starts it in the project, the placeholder literal), a plugin rule is attached in every project, and the hooks' working directory is not the project ([docs/hooks.md](hooks.md#the-jevmem-plugin-for-cursor-076)).* A project set up with `jevmem init --tool cursor` keeps working beside the plugin, which stands down there; `jevmem init --remove-hooks` moves it over.
- **The Cursor rule is a third of its size and says where it does not apply.** The plugin's rule sits in every chat of every project it is installed for, so its body went from 1,287 to 588 characters (about 147 tokens at four characters a token; [results](../results/cursor-rule-cost-2026-10-19.json)), and it opens by telling the agent that a project without `jevmem.config.json` has jevmem off. `init` writes the same text.
- **Cursor's own follow-up line is never a turn of its own** (fix d). After a background task ends, Cursor submits "Briefly inform the user about the task result…" as a user line; when the turn before it had already ended, 0.7.4 decided that line as a new turn (two requests, skipped). It now belongs to the turn before it in every case. *0.7.4's Cursor held-out set, already used by that release's measure, run once on the build as a regression check: 24 of 24 turns paired whole, decide right on save or skip for 21 of 24, the same as 0.7.4's second run ([results](../results/cursor-heldout-2026-10-19-v076.json)).*
- **The pane: a `missed` button, and no recall from another session.** A turn the pane shows as skipped gets a `missed` button that, after a confirm, runs `jevmem missed` with the prompt as typed; and the recall block shows a file only when its `session_id` is this session's, so two sessions in one project never show each other's recall.

**What's new in 0.7.5** (2026-10-17; [CHANGELOG](../CHANGELOG.md#075---2026-10-17)): a pane beside the chat.

- **A side pane shows what jevmem just did.** Install `jevmem-pane` from the jevmem marketplace (`/plugin install jevmem-pane@jevmem`, Claude Code 2.1.299 or newer) and a pane beside your chat shows, for each prompt and turn, the memory lines jevmem gave Claude, what the guard said about a command (the rule and its score, matched to the call), and the line it saved or why nothing was, each with `why`, `wrong` and `forget` buttons; the two that change `JEVMEM.md` ask first, and a rule is retired in a terminal only. It reads three local files and sends nothing ([docs/pane.md](pane.md)). *Measured before it was designed, on Claude Code 2.1.302: the recall file is there by the time the prompt enters the session on 11 of 11 prompts with a memory line, the decision lands 520 to 799 ms after the turn ends (never before, 15 of 15), the guard's entry is found by the call's id on 11 of 11 calls ([results](../results/pane-probe-2026-10-17.json)); its 52 tests, written before the code on real captured files, pass on 2.1.299 to 2.1.302 ([results](../results/pane-tests-2026-10-17-v075.txt)).*
- **The saved line starts at the fact.** A turn written as "Decision for this project: we use pnpm…" or "Rule: never log a request body" used to keep the label; now the writer drops a label that names the kind when a whole sentence follows. *On 12 held-out turns in those forms, run once on the build: 12 of 12 saved, the label kept in 0 of 10 ([results](../results/label-prefix-heldout-2026-10-17-v075.json)).*
- **Three small Cursor fixes from 0.7.4's live check**: `jevmem init --tool cursor` gitignores `.cursor/hooks/state/` (Cursor's own state file lives next to the committable launcher); `jevmem doctor` says when the Cursor app has not started the project's MCP server and names the toggle; and `jevmem wrong <id> --should-be none` on a rule now asks on a terminal, and is refused off one, as `jevmem forget` does ([SECURITY.md](../SECURITY.md#memory-poisoning)).

**What's new in 0.7.4** (2026-10-16; [CHANGELOG](../CHANGELOG.md#074---2026-10-16)): automatic saving in Cursor.

- **A Cursor chat saves like a Claude Code one.** `jevmem init --tool cursor` now writes Cursor's hooks into `.cursor/hooks.json`, with a launcher at `.cursor/hooks/jevmem-hook.sh`, both free of any path of your computer, so they can be committed as Cursor's docs intend. When an agent turn finishes, the `stop` hook reads the turn from the transcript Cursor keeps and runs the same decide and write path as the Claude Code `Stop` hook; a turn you stop is left alone. Reading memory in Cursor stays the agent's `search_memory` call over MCP: Cursor's prompt hook takes no context. *On ten held-out Cursor sessions (24 turns) captured through Cursor's own CLI before the code, the first run on the build paired 21 of 24 turns whole, the prompt with the whole reply and no tool output; the three misses were a user line Cursor writes itself after a background task, read as a new turn, and the fix came from that held-out session, so the second run after it is no longer a first look: 24 of 24 paired whole, decide right on save or skip for 21 of 24 and on kind for 20 of 24, each saved line carrying its labelled words and the one reversal superseded ([docs/hooks.md](hooks.md#cursor-hooks-074), [results](../results/cursor-heldout-2026-10-16-v074-run2.json)).* A project set up for Cursor with an earlier version needs `jevmem init --tool cursor` once more.
- **Cursor's `agent` CLI is covered too.** It fires none of the app's three hooks; each headless `agent -p` run ends with `sessionEnd`, where jevmem decides the transcript's last finished turn. The new `cursor` e2e scenario drives four such runs: a decision saved by the hooks alone, a new chat answering from memory over MCP, an always-on rule reaching the model through `sessionStart`, and a project not turned on sending nothing.
- **The 66-turn benchmark on the build**, as a regression check: `auto` 65 of 66 on save or skip, 63 of 66 with the kind, 5 of 5 contradictions, 234 ms and $0.00019 per decision ([results](../results/eval-heldout-2026-10-16-v074.json)); the README's figures move from 0.22 s and $0.00018 to this run's.

**What's new in 0.7.3** (2026-10-15; [CHANGELOG](../CHANGELOG.md#073---2026-10-15)): the one-time setup message stays silent where it cannot help.

- **No message, no marker, no file in a cloud or Cowork session.** 0.7.2's message showed at the start of every claude.ai chat that ran in a cloud workspace (`CLAUDE_CODE_REMOTE=true`, the entrypoint `remote_cowork`, a new home folder per chat), so "shown once" was every chat, with advice nobody can follow in a workspace, and the marker was written where the next chat could not see it. The plugin's launcher now reads where Claude Code runs from two variables it gives its hooks and shows the message only on your own computer, where the marker stays: a terminal, the desktop app's Code tab, the VS Code extension or an SSH session of the desktop app. A cloud session, Cowork on the desktop, Claude Tag and GitHub Actions get nothing, and so does any entrypoint not placed (a `claude -p` run is `sdk-cli`, measured on Claude Code 2.1.300). The per-session "CLI not found" line in a project that is on stays silent in a cloud or Cowork session too ([docs/hooks.md](hooks.md#the-claude-code-plugin)). *Checked end to end on Claude Code 2.1.301: in a cloud chat's environment, 3 of 3 runs with every hook silent, nothing written and 0 requests, and a control session on the Code tab's entrypoint showing the message ([results](../results/e2e-2026-10-15-v073-remote.txt)); the four scenarios of 0.7.2 12 of 12 ([results](../results/e2e-2026-10-15-v073-message.txt)).*

**What's new in 0.7.2** (2026-10-15; [CHANGELOG](../CHANGELOG.md#072---2026-10-15)): finish the setup in one command, and always-on lines through the gate.

- **Someone who adds the plugin is told once what is left.** After **Add** in the Claude app, the plugin still needs the `jevmem` command, a TypeSafe key and `jevmem setup` in a project; until 0.7.1 nothing said so. Now the first session on a machine says it once, at its start: which step is missing and the one command that finishes it. A terminal prints it as a line from the `SessionStart` hook; in the Claude desktop app's Code tab, which does not draw such lines, Claude passes it on at the start of its first reply. Once per machine, nothing sent, nothing written inside the project, and a marker you can create yourself opts out ([docs/hooks.md](hooks.md#the-claude-code-plugin)).
- **`jevmem setup` finishes the setup in one go**: your key, asked for without showing it and saved as `jevmem key` saves it; the folder turned on; one request to check the key; `jevmem doctor`; and, when the project has past Claude Code sessions, the offer to import them, with the lines shown before anything is written ([docs/install.md](install.md)).
- **Always-on lines go through the poisoning gate.** 0.7.1 served every line marked `always:1` at session start from the file alone, so a line a pull request added with that mark reached every session unchecked. 0.7.2 serves only a verified line or one whose cached gate verdict passed; a line with no verdict gets one on the next prompt, and `jevmem always` and `jevmem add --always` ask the gate when they mark ([SECURITY.md](../SECURITY.md#memory-poisoning)).
- **Jev 1.13.0 is pinned.** TypeSafe's Jev 1.14.0 (2026-10-14) was run on six held-out sets beside 1.13.0: it misses one of the benchmark's five contradictions in every one of three runs, saves fewer captured dead ends in every run (35 to 36 of 47 against 38) and keeps fewer reasons on the written set (19 to 20 of 40 against 22), so the default stays on 1.13.0 until a later Jev measures at least as good ([docs/benchmark.md](benchmark.md#jev-114-against-113-2026-10-15)). A project set up before 0.7.2 follows `jev-latest` from its own config file; `jevmem doctor` says how to pin it.

**What's new in 0.7.1** (2026-10-14; [CHANGELOG](../CHANGELOG.md#071---2026-10-14)): always-on rules, and memory from day one.

- **Rules every change must follow reach Claude in every session.** A line marked always-on (`always:1` in its comment) goes into Claude's context at the start of each session, whatever the prompt, through a new `SessionStart` hook that reads `JEVMEM.md` and nothing else. jevmem marks such a line when it saves it (one more question in the request each turn already sends: is this a standing rule for how any work here is done?), `jevmem add --always` and `jevmem always <id>` mark by hand, and `jevmem always --suggest` proposes marks for a file from before ([How it works](how-it-works.md#always-on-rules-071)). *Why: in 0.6's outcome A/B a convention for every user-facing string was followed 0 of 3 with jevmem and 3 of 3 with the same lines in `CLAUDE.md`, because nothing in "add a button" points at it. On the dev A/B (24 tasks, 72 sessions, Claude Code 2.1.296, `claude-sonnet-5`, 2026-10-13) the marked lines at session start follow that task 3 of 3 and the whole set 66 of 72, as 0.7.0 does; on the held-out sets, run once on the build the same day, 49 of 60 on the first set (0.7.0: 53; `CLAUDE.md`: 52; 4 of the 11 misses stopped to ask for a branch under a rule about `main`) and 18 of 18 on the six tasks whose files predate their conventions (0.7.0: 14; `CLAUDE.md`: 18); on the build itself, on the dev set that chose the design, with its lines marked by hand and on a newer Claude Code (2.1.299, 2026-10-14), 68 of 72 and every convention 18 of 18 ([benchmark](benchmark.md#always-on-rules-071)).*
- **`jevmem import --from sessions` reads a project's past Claude Code sessions** and proposes the decisions, rules and dead ends in them, so memory starts full the day jevmem is set up. It needs a terminal, counts the sessions and turns and estimates the cost before asking `[y/N]`, sends nothing before a yes, decides each turn as the hooks decide a finished turn, oldest first, and writes the lines with `--apply` ([How it works](how-it-works.md#import-srcimportts)). *On 14 real dev sessions (35 turns) it read every turn and found every labelled line (23 of 23) at precision 23 of 26; on the 12 held-out sessions (27 turns), run once on the build, 27 of 27 read, 17 of 17 found, precision 17 of 21, both reversals superseded ([benchmark](benchmark.md#memory-from-past-sessions-071)).*
- **Two contributor changes from the Pi work** ([#38](https://github.com/Avinash-jetwani/jevmem/pull/38), [#39](https://github.com/Avinash-jetwani/jevmem/pull/39)): a drain in the same process no longer steals a live queue lock, and `runHook` takes a project root and returns the recall text for integrations other than Claude Code.

**What's new in 0.7** (0.7.0, 2026-10-09; [CHANGELOG](../CHANGELOG.md#070---2026-10-09)): memory you can see and fix.

- **`jevmem forget <id>` retires a line in place.** A done to-do, a fixed bug, an obsolete rule, a wrong or hand-added line: the line stays in `JEVMEM.md` as `[retired]`, its text unchanged and its old kind in the comment, and recall, the guard, search, the MCP tools and decide treat it as gone. A rule asks for a yes on a terminal, with no flag to skip that, and the guard's tamper check asks before an agent runs the command. `jevmem wrong … --should-be none` now retires instead of deleting. Older versions keep a retired line as text ([How it works](how-it-works.md#memory-file-format)).
- **`jevmem trust <id>` marks a line you wrote as verified**, so `block` mode can deny on your own rules instead of only asking, and recall serves the line without the poisoning gate's question. It needs a terminal, prints the line and asks, runs the poisoning gate and refuses a flagged line, and writes a local, gitignored record that an edit to the line ends ([Guardrails](guardrails.md), [SECURITY.md](../SECURITY.md#memory-poisoning)). `jevmem add --trust` does both at once.
- **Dedupe on save.** A line that says the same as a live one is not saved again: a restatement word for word is skipped before any request, and one more question in the request each turn already sends, read with the line it names, stops a paraphrase. *On a held-out set of 50 turns in five new projects written before the code, run once on each build on 2026-10-08: of 25 restatements (word for word, paraphrased, tagged, quoted), 0.6.6 saved 15 as new lines and 0.7.0 saves 1; restatements that add a detail, reversals and restated retired lines come out the same on both ([0.6.6](../results/dupes-heldout-2026-10-08-v066.json), [0.7.0](../results/dupes-heldout-2026-10-08-v070.json), [benchmark](benchmark.md#memory-you-can-see-and-fix-070)). On the 66-turn benchmark set the counts are 0.6.6's, at $0.000169 against $0.000159 per decision for the question's text.* `jevmem why` names the line a skipped duplicate restates; MCP `add_memory` answers with it instead of an error.
- **A leading tag is not part of a line.** `[constraint] Never …`, a pasted brief's `- [constraint] …`, `[rule] …` or `[note] …` no longer end up as `[constraint] [constraint] Never …`: the writer, `jevmem add`, `jevmem import` and MCP `add_memory` drop the tag; a bracketed token that is not a kind or a label (`[DEPRECATED] …`) stays. *24 held-out texts, run once on each build: 0 of 18 tags stripped on 0.6.6, 18 of 18 on 0.7.0, the six bracketed tokens that must stay kept on both ([results](../results/tagstrip-heldout-2026-10-08-v070.json)).*
- **Two local files for a side pane** (the pane itself came in 0.7.5): `.jevmem/last-recall.json` (what the last prompt got) and `.jevmem/last-decision.json` (what the last turn's decision was), and the call's id in the guard's log ([docs/hooks.md](hooks.md#local-files-for-the-pane)). They stay on the machine.

**What's new in 0.6** (0.6.0, 2026-09-30; [CHANGELOG](../CHANGELOG.md#060---2026-09-30))

- **Dead ends.** jevmem saves an approach that was tried and failed, with the reason, and puts it in front of Claude as "Already tried: …" when a prompt comes back to it. A later turn that shows it works now supersedes it ([docs/dead-ends.md](dead-ends.md)). *Decide's held-out v3 set, 100 turns in five new projects, run on the 0.6.5 build on 2026-10-05, after its writer change (earlier runs: 2026-09-27, and on the 0.6.0 build on 2026-09-30 with the same counts): dead ends saved 25 of 25, every one with its reason (25 of 25); reversals of a saved line superseded 10 of 10 ([results](../results/dead-ends-heldout-v3-2026-10-05-v065.json)). In the outcome A/B below, Claude never repeated an approach recorded as failed (0 of 15 sessions), against 3 of 15 with no memory; the same lines in `CLAUDE.md`: also 0 of 15.*
- **Recall that finds the lines a prompt needs, and nothing for a prompt that needs none.** Every live line is asked about, each on its own. *Retrieval held-out v2: 90 prompts over three new projects of 20, 80 and 250 lines, run once on 2026-09-28, 0.6 (`48cc67d`, the recall code that ships) against 0.5.9: recall 75/78 against 55/78 (18 of the 78 wanted lines are dead ends, which 0.5.9 cannot read; on the other 60, 0.6 found 57 and 0.5.9 found 55); lines injected that were wanted or fine 96/97 against 88/104; unrelated prompts that got a line 1/18 against 5/18; superseded lines injected 0 of 90 in both. Prompts that need two lines got both in 3 of 6. Cost per prompt $0.000578 against $0.000267, and $0.001002 against $0.000320 on the 250-line file. Above 250 live lines, only the 250 sharing the most words with the prompt are asked about (a 500-line dev file: recall 37/46).*
- **A slow or failed Jev call no longer means no memory.** Past one second, the prompt gets the lines that share the most words with it. *On held-out v2 no call ran late (hook p95 596 ms; 0.5.9's, in the same run, 491 ms), so this served no prompt there. Word match finds lines that share the prompt's words (on dev, as if every prompt had fallen back, 25 of 32 for prompts that name what they need) and seldom the others (3 of 33).*
- **Claude acts on the saved line about as often as with `CLAUDE.md`.** "With jevmem, Claude followed the project's saved line in 66 of 72 sessions; with the same lines in `CLAUDE.md`, in 67 of 72; with no memory, in 28 of 72." *24 tasks in three small projects of 34 to 42 saved lines, 3 runs each, real Claude Code 2.1.281 sessions with `claude-sonnet-5`; the jevmem arm on 0.6 (`48cc67d`, 2026-09-29, the same 66 of 72 as on part 3's build; the recall code that ships), the other two arms in part 3's run (2026-09-28). `CLAUDE.md` did better where nothing in the prompt points at the line (a convention for every user-facing string: 3 of 3 against 0 of 3); until 0.7.1's always-on rules (above), rules every task must follow belonged there.*
- **The guard, a backstop.** A `PreToolUse` hook checks each Bash, Edit and Write call against your saved rules, and has Claude Code ask you (or blocks the call) when Jev says it may break one ([docs/guardrails.md](guardrails.md)). *In the A/B's 6 constraint tasks (18 sessions, rerun on the release build on 2026-09-30 with Claude Code 2.1.284), recall kept Claude from ever attempting the forbidden change (0 of 18; 10 of 18 with no memory in the 2026-09-28 run), and the guard checked all 78 of those sessions' Bash, Edit and Write calls and asked once: an edit to the output formatter that put a new format behind a new flag, as its rule allows (Jev 0.89); in `claude -p` that ask refused the edit, and the session finished the task another way, 18 of 18 followed the rule and 17 of 18 did the task ([results](../results/ab-guard-2026-09-30.json)). On the guard's second held-out set (274 calls in five new projects, written after a day's trial in jevmem's own repository; run once on the 0.6.0 build on 2026-09-30 and once on 0.6.1 the same day): violations caught 66/68 and the check that guards jevmem's own files right on 274/274 calls in both runs, and false asks 3–4 of 206 across the two (the one call that differs is `git add token.secret.example`, which breaks no rule: 0.52 in the 0.6.0 run, then 0.47, either side of the 0.5 threshold; the command has no bracket, so that is Jev's variation between runs, not the fix) ([docs/guardrails.md](guardrails.md#the-test-command-after-a-reserved-word-061)).*
- **Background subagents.** A turn that hands work to a subagent in the background is decided once, when it is over, not while the subagent works, and the subagent's report is never read as your message. *Decide held-out v4: 30 real Claude Code 2.1.281 sessions, 14 with a background subagent, replayed through the release build and 0.5.9 in one run on 2026-09-30 (first run 2026-09-28): lines saved while a turn was still running 0 (0.5.9: 9), lines decided from a subagent's report read as your message 0 (0.5.9: 13), turns saved or skipped right 32 of 33 (0.5.9: 27 of 33) ([results](../results/stops-heldout-v4-2026-09-30-v060.json), [0.5.9](../results/stops-heldout-v4-2026-09-30-v059.json)). The line is the sentence that states the memory, not the request or hand-off next to it: on a line-text held-out set of 64 saved turns in four new projects (16 of them a memory next to a request or a hand-off to a subagent), run on the 0.6.5 build on 2026-10-05, after its writer change (first run 2026-09-29, with 0.5.9 beside it), the saved lines stated the fact in 64 of 64 (63 of 64 in a run one commit earlier that day; 0.5.9: 41 of 59), kept the reason in 29 of 30 (0.5.9: 5 of 25), and none was a request or a hand-off (0.5.9: 13 of 59) ([results](../results/lines-heldout-2026-10-05-v065.json)).*

- **0.6.1 and 0.6.2 fixed the guard skipping a Bash call with `if [ … ]` or `while [ … ]` in it** (0.6.0's check threw on the `[` and the hook stayed silent, so the call ran unchecked; 0.6.2 is 0.6.1's code, published again): [docs/guardrails.md](guardrails.md#the-test-command-after-a-reserved-word-061), [CHANGELOG: 0.6.1](../CHANGELOG.md#061---2026-09-30), [0.6.2](../CHANGELOG.md#062---2026-09-30).
- **0.6.3 fixes what you see, not what is saved, recalled or checked:** `jevmem doctor` shows the plugin synced from claude.ai once, its newest copy, where an update had left the previous copy beside it and doctor listed both; the [limits](limits.md#honest-limits) and the [upgrade notes](upgrading.md) say what an open session loses when that plugin updates, and what to do; `scripts/eval.mjs` records the version of the build it measured ([CHANGELOG](../CHANGELOG.md#063---2026-09-30)).
- **0.6.4 is docs only:** the README is rewritten short, with graphics, and what moved out of it is on this page, [install.md](install.md), [upgrading.md](upgrading.md) and [limits.md](limits.md); nothing changes in what jevmem saves, recalls or checks ([CHANGELOG](../CHANGELOG.md#064---2026-10-01)).
- **0.6.6 saves a failed attempt as a dead end, not as a decision.** When you ask Claude to try or change something and its reply says that failed and why, jevmem now reads the reply (one small extra request with its first 2,000 characters, asking only whether it reports a failed attempt) and saves the dead end instead of the request. On 40 written held-out failed attempts, 0.6.5 saved 12 as dead ends and the request itself as a decision or a to-do in 21; 0.6.6 saves 37 and the request in 2. On 47 captured from real Claude Code sessions: 28 and 15 against 37 and 3 ([docs/benchmark.md](benchmark.md#a-failed-attempt-is-not-a-decision-066)). The reply is sent on more turns ([PRIVACY.md](../PRIVACY.md)); `"jev": { "askAboutReply": false }` keeps 0.6.5's behaviour. The line keeps the labelled cause in about half of those dead ends, and a first failure put right on the way can read as a failed attempt ([limits](limits.md#known-limits)).
- **0.6.5 keeps a dead end's reason when Claude's reply gives the verdict first and the cause last.** In the release's own end-to-end runs, 3 of 6 dead-end lines had lost it: "It didn't work, so I'm dropping the idea …" took the room, and the line was cut before "because". *On 18 turns written in that style before the fix (held-out, one run on each build, 2026-10-05): with the reply given to the writer as a dead end, 12 of 13 lines keep the reason (0.6.4: 2 of 13), and 5 of 5 lines for a turn that makes a dead end work say what was changed (0.6.4: 1 of 5). With decide in front, 6 of the 13 dead ends are saved as one, each with its reason (0.6.4: 2 of the 6 with it); in the other 7 decide does not read Claude's reply, in 0.6.4 and 0.6.5 alike ([benchmark](benchmark.md#the-cause-last-065), [limits](limits.md#known-limits)).* Also in 0.6.5: `jevmem init --tool claude-desktop` prints `<your TypeSafe API key>` where your key goes (it printed `your-key`), and the descriptions and links on npm, in the plugin and on the MCP Registry point at the [docs site](https://avinash-jetwani.github.io/jevmem/). Recall and the guard are unchanged ([CHANGELOG](../CHANGELOG.md#065---2026-10-05)).

## Earlier releases

- **In the Claude plugin directory** (2026-09-29): add jevmem from the Claude app. The plugin runs the `jevmem` CLI from npm, so setup takes three commands.
- **0.5.10, clearer setup for installs from the Claude plugin directory** (`jevmem@synced`): `jevmem key` saves your key, the first prompt says when no key is found and how to fix it, `jevmem doctor` sees the directory's plugin, and `jevmem enable` gives one next step. No change to what is saved or recalled. Upgrade with `npm install -g jevmem@latest` (plugin users too: the plugin runs this CLI) ([CHANGELOG](../CHANGELOG.md#0510---2026-09-29)).
- **0.5.8, a security fix: secrets named like `PGPASSWORD=` weren't scrubbed in 0.5.7 and earlier.** A prompt or turn with `PGPASSWORD=…`, `MYSQLPWD=…` or `"password": "…"` in it was sent to TypeSafe with the value as written. Upgrade with `npm install -g jevmem@latest` (plugin users too: the plugin runs this CLI), and rotate any such secrets that were in your chats in an enabled project ([advisory GHSA-2r3p-5hmg-46p5](https://github.com/Avinash-jetwani/jevmem/security/advisories/GHSA-2r3p-5hmg-46p5), [CHANGELOG](../CHANGELOG.md#058---2026-09-28)).
- **Install as a Claude Code plugin** (0.5.0), opt-in per project since 0.5.1: it does nothing until you run `jevmem enable` in a repo.
- **A memory-poisoning check on recall** (0.5.0): lines that jevmem did not write on your machine (a teammate's, a pull request's, your own hand edits) are checked by Jev before they're added to Claude's context. In our 44-line test set (2026-09-25) it blocked 20 of 22 planted lines, with 0 of 22 false blocks on legitimate rules ([SECURITY.md](../SECURITY.md#memory-poisoning)).
- **Turns queued during Jev outages** (0.5.0) and retried later, in order, instead of being dropped.
- **`jevmem import`** (0.5.0) for an existing `CLAUDE.md`, `AGENTS.md` or Cursor rules.
- **Saving runs in the background** (0.5.0): the `Stop` hook is async, so Claude doesn't wait for it. On v0.5.6 its process exited in 12–14 ms, and the decision was recorded 0.26–0.28 s after it started ([results](../results/ops-2026-09-26-v056.json)).
- **No calls to OpenAI or Anthropic unless you set `writer`** in `jevmem.config.json` (0.5.4). A key in your environment is not enough on its own.
- **[PRIVACY.md](../PRIVACY.md)** (0.5.7): no telemetry, and exactly what goes where, with the third parties' privacy policies and how to delete your data.
