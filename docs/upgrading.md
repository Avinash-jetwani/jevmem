# Upgrading

**Upgrading to 0.7.2.** `npm install -g jevmem@latest`; the plugin's `SessionStart` entry gains a flag (`--start`), so the directory and marketplace plugins move to 0.7.2 with the CLI (a 0.7.2 plugin with a 0.7.1 CLI prints the usual "older than this plugin" line; its one-time setup message needs no CLI at all). What changes for you: an always-on line is served at session start only when it is verified or the poisoning gate has passed it, so a line you marked on 0.7.1 by hand on a line jevmem did not write waits for its verdict until your next prompt; `jevmem always <id>` and `jevmem add --always` now ask the gate once ([PRIVACY.md](../PRIVACY.md)). The default Jev model is pinned to `jev-1.13.0`; a `jevmem.config.json` written before 0.7.2 says `"model": "jev-latest"` and follows TypeSafe's alias (to 1.14.0 from about 2026-10-21): `jevmem doctor` says so, and `"jev": {"model": "jev-1.13.0"}` pins it ([configuration](configuration.md)).

**Upgrading to 0.7.1.** `npm install -g jevmem@latest`, and the plugin gains a fourth hook, `SessionStart`: the directory and marketplace plugins move to 0.7.1 with the CLI (a 0.7.1 plugin with a 0.7.0 CLI prints the usual "older than this plugin" line, and its SessionStart hook runs a CLI that ignores the event); with `jevmem init` hooks, run `jevmem init --tool claude` again in each project to add the hook (nothing else changes). A `jevmem.config.json` from before has no `alwaysOn` and no `thresholds.alwaysMin` and gets the defaults (`always`, 0.5). Lines saved before 0.7.1 carry no always-on mark: `jevmem always --suggest` proposes marks for the live rule-like lines and `--apply` sets them, or mark by hand with `jevmem always <id>`. A line marked always-on (`always:1` in its comment) is read as usual by a 0.7.0 teammate, whose jevmem drops the mark when it rewrites the file. One more question leaves the machine in the request each turn already sends (asked in each tier), no new text ([PRIVACY.md](../PRIVACY.md)); `jevmem import --from sessions` reads past sessions only when you run it and say yes.

**Upgrading to 0.7.0.** From 0.6.0 to 0.6.6, `npm install -g jevmem@latest` is the whole upgrade: the plugin's hooks have not changed since 0.6.0, and the directory and marketplace plugins move to 0.7.0 with the CLI. 0.7.0 asks one more question in the request each turn already sends ([PRIVACY.md](../PRIVACY.md)); a `jevmem.config.json` written earlier has no `thresholds.duplicateMin` and gets 0.7. `jevmem wrong … --should-be none` now retires the line instead of deleting it, and a `[retired]` line stays in `JEVMEM.md`: a teammate still on 0.6.x keeps it as text, and moves it after the memory lines when their jevmem rewrites the file. Nothing else changes in what is saved, recalled or checked.

**Upgrading to 0.6.6.** From 0.6.0 to 0.6.5, `npm install -g jevmem@latest` is the whole upgrade: the plugin's hooks have not changed since 0.6.0, and the directory and marketplace plugins move to 0.6.6 with the CLI. 0.6.6 reads Claude's reply on more turns ([PRIVACY.md](../PRIVACY.md)); `"jev": { "askAboutReply": false }` in `jevmem.config.json` keeps 0.6.5's behaviour. From 0.5.x, one of the paths below, tested on 2026-09-30 on the 0.6.0 build in a temporary HOME with a project set up on 0.5.10 that kept its lines ([results/upgrade-2026-09-30.txt](../results/upgrade-2026-09-30.txt)); 0.6.1 to 0.6.6 change nothing in them:

- **From the Claude plugin directory (`jevmem@synced`)**: `npm install -g jevmem@latest` brings everything the two hooks run, dead ends, the new recall, the line made from Jev's sentences, the subagent fix, and `jevmem guard test`, at once. The guard's `PreToolUse` hook is in the 0.6.x plugin, which the directory serves after the release moves its `directory` branch; until your app syncs it, the new CLI runs under the two hooks of the 0.5.7 plugin and the guard is off in plugin sessions. Claude Code downloads plugin updates in the background each time it starts ([Claude Code docs](https://code.claude.com/docs/en/plugins/loading#synced-plugins)), and a session that is open then says `Plugins changed. Run /reload-plugins to activate.`; `jevmem doctor` shows which plugin version is on disk and which CLI its hooks run. If doctor still shows the old version, start `claude` once in a terminal, signed in with the same Claude account as the app: that is what picked up 0.6.2 on the author's Mac.
- **From the jevmem marketplace (`jevmem@jevmem`)**: `npm install -g jevmem@latest`, then update the plugin in Claude Code (`/plugin`, or `claude plugin update jevmem@jevmem`); Claude Code picks up the new plugin because its version changed. With the 0.6.x plugin and an older CLI, the plugin prints one warning line and skips the guard's hook.
- **With `jevmem init` hooks**: `npm install -g jevmem@latest`, then run `jevmem init --tool claude` again in each project: it adds the `PreToolUse` hook next to the two it registered before and changes nothing else; `JEVMEM.md`, `jevmem.config.json` and `.jevmem/` are kept. Until then the two existing hooks already run the new CLI, and `jevmem doctor` says the guard hook is missing. A `jevmem.config.json` written by an earlier version has no `guard` block and gets the defaults (`ask` mode).
