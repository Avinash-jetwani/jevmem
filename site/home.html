Claude remembers you. jevmem makes your project's rules stick.

Project memory for Claude Code, Cursor and Codex. jevmem keeps your project's decisions, rules and failed approaches in one file in your repo, brings them back in later sessions, and checks Claude's commands against them before they run.

What it adds to Claude Code

1

The guard: rules checked before Claude acts

jevmem checks Claude's commands and file edits against your saved rules. If one may break a rule, Claude Code stops and asks you first.

jevmem: this may break
a saved rule:
  "Don't hand-edit
   db/migrations/"
the guard →
2

One JEVMEM.md, shared through git

Your project's memory lives in JEVMEM.md in your repo. Teammates get the same rules when they pull.

[decision]
  We use pnpm, not npm.
[dead-end]
  In-memory cache broke
  the build: keep Redis.
CLAUDE.md or JEVMEM.md →
3

Claude Code, Cursor and Codex

The same file works across your AI coding agents, and in Claude Desktop over MCP. It runs beside Claude Code's auto memory.

Install

$ npm install -g jevmem
$ jevmem setup   # in your project's folder

First add the plugin in the Claude app: Plugins → Discover → jevmem → Add. Needs Claude Code 2.1.273 or later and a TypeSafe API key. Upgrading to {{version}}: npm install -g jevmem@latest, then re-run jevmem init in a project set up with init. Every install path
