# How a plugin user sets or changes the sensitive typesafe_api_key option, checked in Claude Code's TUI, 2026-09-27.
# scripts/plugin-configure-check.py --claude <binary>, once with 2.1.274 (the CLI on this machine's PATH) and once with
# 2.1.281 (the desktop app's bundle), on the part 1e working tree before its commits. The plugin is installed from a marketplace NOT
# called jevmem ("not-jevmem"), so nothing here depends on the marketplace's name. Jev is a local stand-in (simulated,
# not the real Jev) that records the key each request carries; the keys are fake test values.
# A: /plugin configure jevmem (no marketplace name). B: the same, again, with another key. C: the path Claude Code's docs
# describe (/plugin, the Installed tab, jevmem, Configure options). D: claude plugin install --config on the installed
# plugin (informational). Each is followed by a headless session in an enabled project whose hooks must send that key.
#
# Also on both versions, for reference:
#   claude plugin --help            lists details, disable, enable, eval, help, init, install, list, marketplace, prune,
#                                   tag, uninstall, update, validate: no configure (it is a /plugin subcommand in the TUI)
#   claude plugin install --help    "--config <key=value>  Set a userConfig option declared in the plugin's manifest
#                                   (repeatable). Values are validated against the schema and stored via the same path
#                                   as the interactive /plugin configure flow."
#   /plugin help (in the TUI)       "/plugin configure <plugin> - Set userConfig options"
#   claude plugin uninstall jevmem  "Successfully uninstalled plugin: jevmem" with the plugin from not-jevmem
#
